# 会话小结 2026-10-09：P1-6 阶段C（app.js 模块化）落地

## 做了什么

外审修复计划 P1 批次的最后一块：`web/js/app.js`（3320 行单文件）拆为
`web/js/` 下 13 个经典 script 模块，index.html 按原单文件区块顺序加载。
终版 **pytest 1049 passed + tests/ui_smoke.py 85/85**。

## 方案取舍（防回退）

- **刻意不用 ES modules**：index.html 有 66 处内联 onclick，动态生成 HTML
  里的处理器也走全局作用域；ES modules 要手工导出几十个 window 绑定，
  漏一个就是只有真机才能发现的运行时错。改为**保序字节级切割**：
  13 文件加载序 = 原文件序，语义不变由构造保证。
- **等价硬证据**：模块拼接（去 7 行头注释）== `git show HEAD:web/js/app.js`
  逐字节一致（136393 B）；node --check 全过；内联处理器引用的 37 个全局名
  全部仍存在。
- **验收没等手工双击**：台账原以为「需手工 GUI 冒烟、本环境做不了」，
  实际 `tests/ui_smoke.py`（Playwright 真机 + stub LLM）可全覆盖
  （发消息/切会话/热力图/设置/启动），85/85 通过。

## 坑位（重要）

1. **顶层可执行语句不许被切缝劈开**：首刀把 `eel.expose(onPCBChanged)`
   留在 utils.js 末尾而函数在 stream.js → 加载即 ReferenceError。
   node --check 只查语法、字节拼接只证内容，**只有 ui_smoke 抓得住**。
   再切任何文件时，先扫缝线两侧的顶层语句。
2. **Python 动 JS 文件一律 binary read/write**：`Path.write_text` 在
   Windows 做 LF→CRLF 翻译，缝上修补时引入 128 个 \r，等价断言抓回。
3. 一次性拆分脚本按惯例已删；等价校验思路：7 行头注释 + 拼接比对 git 基准。
