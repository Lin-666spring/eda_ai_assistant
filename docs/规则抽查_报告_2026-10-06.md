## 0. 一句话结论

**判据修复把违规总量砍掉 44%（5769 → 3241），但抽样精确率没有提升**：
总体 7.7% → 6.5%（95% CI 大幅重叠），走线类 11.1% → 10.8%，非走线类 5.5% → 3.6%。
也就是说：修复解决的是**噪声的量**，没有解决**判据本身的有效性** —— 剩下能报出来的违规里，
仍只有约 6.5% 是这块板上真该改的问题（另有 29.9% 属「任何板都会响」的通用提示）。

## 4. 本轮确认的判据缺陷（按「改起来最值」排序）

> 均为判读时逐条回源码 + 原始数据核实；`rule_func` 可直达 `src/rules/checker.py`。

**A. 明确的代码 bug**（复查后确认 3 条；judge 报的第 4 条已撤销，见下）

1. `_check_trace_acute_angles` 的**过孔锚点从未生效**：`checker.py:1368` 用
   `getattr(v, "x"/"y")` 取过孔坐标，而 `PCBVia` 只有 `position`（`models.py:25-27`）→
   `anchor_grid` 里没有过孔，焊盘/过孔入口过滤对「顶点落在过孔上」的拐角全部漏放。
2. ~~`_is_pad_entry` 用 `max(leg_in, leg_out) < 0.5`，与注释「两腿均短于 0.5mm」不符~~
   —— **2026-10-06 复查：该判读不成立，本条撤销**。`constants.PCB.TRACE_CORNER_PAD_LEG_MM` 的注释原文是
   「两腿均短于此值且贴近焊盘/过孔 → 焊盘入口几何」，而 `max(leg_in, leg_out) >= pad_leg → return False`
   正是「两腿都短才算入口」，代码与常量注释一致；judge 举的 0.374/0.602mm 拐角按定义本就不属焊盘入口
   （真正让它被误报的是上面第 1 条的过孔锚点缺失）。
3. `_check_opamp_feedback_network` 用「与运放同前缀的电阻」计数，U 前缀 vs R 前缀**恒为 0** → 结构恒真。
4. `_check_reference_continuity` 只取每行第一个位号（`"R4,R5"` 只算 R4）→ 报出不存在的跳号。

**B. 用「存在性/子串」代替「网表/几何」**（FP 的最大来源）

5. `_check_crosstalk_spacing`：**把工程声明的差分对「自身两半」当串扰对**（本轮 5 条串扰样本全部因此判 FP）。
   类别门控只要求「至少一侧是 diff/high」，同一差分组的两条网络于是互为候选，而差分对本来就要平行跑全程
   （≈2W 边耦合）、重叠长度必然最大 → 每层「最严重」几乎总是对内耦合。证据：AirLink Bottom 21 对里 17 对
   是差分组自身（HSD0± 0.257mm=1.98W/26.8mm）、Mini-LinuxPC 17 对里 11 对（USB0_DM/DP 2.07W/55.4mm）、
   泰山派 3 对（PCIE0_REFCLKN/P 2.71W、LPDDR5_WCK1N_B/P 2.67W）。修法：两网同属一个声明差分组时跳过。
   同一规则还残留「名字猜配对」（`diff_pair_*` 已要求 `source=='engine'`，串扰规则没有）。
6. `_check_diff_pair_spacing`：缺高速接口门控（`_HIGH_SPEED_IF_KW` 只在阻抗规则里有）→ 音频/UART/RC 节点
   只要被设计者用 `differentialName` 标了组就判；且只比「最小距离」不看平行重叠
   （两网各 0.78mm 走线、重叠 0.0mm、相距 2.842mm 也报「耦合过松 11.2W」）。
7. `_check_antenna_keepout`：`wireless_kw` 含裸 `"rf"` → `Q3`(IRFZ44N MOSFET) 被判无线模块。
8. `_check_power_loop_area` / `_check_switching_regulator_layout`：`dcdc_kw` 裸 `MP/XL/SY/MT`
   → LED `XL-1608`、晶振 `XL7EL89`、ESD `RCLAMP0524P`、磁珠 `MPZ1608`、轻触开关 `…SMTR…` 全中。
9. `_check_ferrite_bead_isolation`：`analog_kw` 裸 `'op'` 命中 `ESOP8`/`MSOP8`。
10. `_check_pullup_pulldown` / `_check_dcdc_feedback_network` / `_check_led_current_limit` /
   `_check_decoupling_cap_per_pin` / `_check_i2c_pullups`：用「BOM 行的描述里有没有『电阻/电容』字样」
   代替网表判据 —— 本项目大量 BOM 行 `description` 为空或只有 `0805`/`Res_0603`，于是**恒报**。
11. `_check_mosfet_gate_resistor`：只问「BOM 里有没有电阻行」，与栅极网络无关（栅极网上就有 R21）。
12. `_check_crystal_load_caps` / `_check_crystal_frequency`：晶振识别用裸 `mhz/khz`（命中蜂鸣器、
    磁珠、DC-DC、MCU 主频）；频率→CL 表不看器件自身规格（器件写 12pF、板上就是 12pF，却建议 18~22pF）。
13. `_check_net_antenna`：`len(pins)<=1` 把**零引脚网络**也算单端网络（该板 `orphan_pad_nets=77`）。
14. `_check_via_density`：网名裸 `SW` 命中 `…BUZZER_SWITCH`，把拨码开关网络当高速网络。
15. `_check_esd_protection` / `_check_emi_filter` / `_check_reverse_polarity_protection`：同样靠
    描述子串认「外露接口/电源入口/保护器件」→ `SN74HC125PWR` 后缀、LDO 的「Vin=18V」都成了入口，
    真器件 `SS54`/`P6SMBJ6.0CA`/`AO3401`/`TPS259261` 全漏。

## 5. 结论与建议

1. **论文口径**：报「判定类覆盖率 43/57（75.4%）+ 抽样精确率 6.5%（95% CI 3.0~13.5%）」并附样本量与证据文件；
   不要再使用「有输出 57/71 = 80%」当准确率，也不要声称修复提升了精确率（**证据不支持**）。
2. **下一轮修复的优先级**：先修 §4A 复查确认的 3 个代码 bug 与 §4B 的「存在性代替网表」（这两类直接决定 FP 主体），
   再处理 §4C 的坐标系问题；每修一条都重跑 dump 看违规量与抽样精确率是否真的动了。
3. **提示类规则要单列**：`ADVISE_RULES` 的 14 条贡献 937 条违规（29%），其中多条每板必响；
   产品里应有独立开关与「这不是针对本板的判定」的措辞，覆盖率口径也不该把它们算进判定类。
4. **判读必须配证据**：本轮每条判读都落到「哪个位号/哪个网络/哪个数值」，报告才可复核；
   这也暴露了 `description` 大量不可用于判读。
