## 1. 问题定义

- 口径 A（可判定）71/71：规则的数据守卫通过 → 它对这块板做了判断。
- 口径 B（有输出）61/71、违规 5769 条：规则产出了 ≥1 条违规。

「有输出」衡量的是**活跃度**，不是正确性：没有标注真值，误报与真缺陷混在一起，
而违规总数对阈值极度敏感（8394 → 4000 → 5769），所以需要人工/AI 抽查给**精确率与区间**。

## 2. 方法

| 步骤 | 脚本 | 产物 |
|---|---|---|
| 全量导出违规明细 + 判读证据 | `scripts/rule_spotcheck_dump.py` | `violations.jsonl`（5769 条，与覆盖率实验逐条对齐） |
| 按规则分层抽样 | `scripts/rule_spotcheck_sample.py` | `sample.jsonl` / `sample.csv`（走线类 5 条/规则、其它 2 条/规则，共 **150 条**，seed 20260918） |
| 合并判读 + 计分 | `scripts/rule_spotcheck_judge.py` / `rule_spotcheck_score.py` | `judged.jsonl` / `report.txt` / `metrics.json` |

**判读口径（四分类，避免把「通用提示」混进精确率）**

- **TP** 违规成立：证据支持判据，且是这块板上真该改的问题；
- **FP** 误报：判据/几何/数据用错，或该处根本不是问题；
- **GEN** 通用提示：不是对这块板的判定（任何板都会响、无法证伪）；
- **UNC** 无法定性：需要规则之外的信息（信号速率、叠层、BOM 真值）。

精确率 = TP/(TP+FP)，Wilson 95% 区间；GEN/UNC 单列，另报「UNC 全算误报」的保守下界。

**差分对/串扰类判读采用的量则**（避免「凭感觉」）：

- 差分对长度：接口对偏斜不敏感（音频功放、直流输入、USB2 且偏差 <2% 位周期）→ FP；
  组内极差 ≥2mm 或 ≥10% 走线长度（与设计者显式声明的等长/差分约束明显矛盾）→ TP。
- 差分对间距：3.0~4.5W 属阈值边界 → FP；≥4.5W 明显松耦合 → TP；靠名字猜测的配对一律 FP。
- 串扰：线对里主要是电源/地、或全是低速网络（按键、蜂鸣器、32kHz、GPIO）→ FP；
  线对性质无法判定（$1N* 无名网络/开关节点混排）→ UNC。
- 拐角：**逐条看该违规对应的那一个拐角**（不是看网络汇总）——腿长 <0.5mm 且离焊盘/过孔 <1mm 判为焊盘入口几何 → FP；
  直角规则只输出 INFO 且规则自述「低速线可接受」→ GEN。

**每条判读都基于可核对证据**，不是只看描述文本。证据在 `violations.jsonl` 的 `evidence` 字段：

- 线宽类：该网络**按长度加权**的线宽分布、窄段占比、窄段到最近焊盘/过孔的距离；
- 拐角类：每个拐角的内角、两条腿长度、到最近过孔/元件/板框的距离、被最小腿长门限滤掉的退化拐角；
- 串扰类：重算该层全部「平行重叠 ≥5mm 且间距 <3W」的线对（网络名/间距/平行长度/线宽比）；
- 差分对：工程 NET 规则里**整组**成员的长度与极差、分组来源（工程规则 or 名字猜测）；
- 电源类：估算电流、IPC-2221 实际载流（外层/内层两种口径）、所需线宽。

同时在 `src/rules/checker.py` 上做了独立**代码核查**（3 个子任务，逐条给行号），
确认判读依据的是代码真实行为，而非描述文本的自述。

## 6. 误报模式 → 代码位置 → 修法

（本节每条都经代码核查确认，行号对应 `src/rules/checker.py` 现状）

1. **电源载流按内层降额算了外层线**（1101-1102、1113-1114）
   `is_inner` 对**整板所有电源走线**做 `any()` 得到一个板级布尔，然后每个网络都用它；
   IPC k 系数 0.024(内)/0.048(外) 使容量**严格减半**。76 块板里 **23 块**同时有内层+外层电源线 → 外层线被误判。
   抽样 5/5 全是这种误报（例：VCC5V 0.254mm 报「载流 0.44A < 需求 0.78A」，外层实为 0.89A）。
   **修**：`is_inner` 改为按**该网络当前这条 trace 的层**判定；min-width 也要记录所在层。
2. **特征阻抗把单端 Z0 和差分目标阻抗直接比**（2344-2351、2367-2370、2353、2360-2362）
   目标表是差分值（USB 90/HDMI 100/LVDS 100/ETH 100），却调用单端 `microstrip_impedance`；
   `calculator.py:183` 里已有 `differential_impedance` 却没用；介质固定 0.2mm/er=4.5 不看叠层；
   只分析 `traces[:50]`；按网络名子串命中即报 ERROR（HDMI_TX_SDA、HDMI_HCEC、USB_VBUS 全中）。
   **修**：差分网络用差分公式与差分目标；读叠层参数；限定真实高速网（差分对成员/时钟），并对非高速命中降级。
3. **短桩线判据与 stub 无关**（2044-2051）
   只按「过孔的网络名含 CLK/USB/HDMI/…」就报「可能存在 stub 效应」，全程没有长度/分支测量；
   二层板（Top/Bottom，例如抽样的 PCIe 扩展卡）根本不存在 stub。
   **修**：需要连接拓扑（T 分支长度），或至少限定 ≥4 层并排除「仅换层过孔」。
4. **信号线宽两条判据都偏**（constants.py:234-235、1066-1069）
   绝对下限固定 0.1mm，不区分层数（4/6 层常规能力 0.09mm）；相对判据是「本板信号线宽众数 ×0.6」，
   把**整条网络统一选细**的设计意图当成误设。抽样 5/5 误报（0.127mm 统一网络、3.5mil 阻抗控制线）。
   **修**：下限按层数（≥4 层 0.09mm）；相对判据要求「同一网络内混用多种线宽」才报。
5. **串扰判据没有速率门限、且把电源/地算进来**（1412-1471）
   实测线对里是 +5V/PGND(0.1W)、GND/USB_VBUS、按键/蜂鸣器、32kHz 晶振、GPIO——3W 准则对它们没有意义。
   **修**：排除电源/地网络对（或改用「最小线距」DFM 规则单独判）；按网络类别（时钟/差分/高速）门控。
6. **拐角规则**（1163-1221）
   直角对所有网络一律 INFO，规则自己也写「普通低速线可接受」；锐角只过滤了腿长 <0.05mm，
   抽样里 2/3 的锐角其实是**焊盘入口几何**（腿长 0.21mm、距元件 0.43mm）。
   **修**：直角只对高速/时钟网络报；锐角加「到焊盘/过孔距离」二次过滤，或按严重度分级（<60° 才 WARNING）。
7. **差分对门限不分接口速率**（constants.py:277-278）
   0.5mm 失配 / 3W 间距对 USB2（位周期 2083ps，3.25mm≈22ps）、音频功放、直流输入 ± 都过严；
   靠 P/N、± 后缀猜出来的「差分对」（D1_P/D1-、IN_D+/IN_D-）根本不是差分信号。
   **修**：只用工程 NET 规则的差分/等长组；猜测配对降级为 INFO；门限按接口类型分档。
8. **提示类规则混进「有输出」**（第 5 节 13 条）
   **修**：ToolDef/规则元数据里加 `kind: detect | advise`，覆盖率只报 detect 类，advise 类单列。
9. **BOM 类判据有确定性 bug**
   - 参数范围检查（636-649）：E24 查表 `mantissa*100` 与 `e*10` 比较，**差 10 倍** → 20kΩ/22µF/100nF/100K 全被判「非 E24」（73 块板 779 条）。
   - 电容耐压降额（912-915）：正则在 value+料号里搜 `(d+)V`，把料号 `…R0VH…` 抓成 0V → 报「耐压 0.0V，裕量不足」。
   - 器件类型靠**裸子串**匹配：`XL-1608`(LED)→开关稳压器、`NanoSIM` 含 si→功率 MOSFET、含「功率:60mW」的 LED→功率电阻；DC-DC 白名单还命中 MPU6500/磁珠/钽电容；MOSFET 规则算出的 `has_gate_r` 从未参与判断。
10. **其它逻辑问题**
    - 铜皮连接检查（1496-1509）：只有**缺铜皮数据**时才报一条 INFO，有铜皮时恒空 → 属于「数据缺失」不是缺陷。
    - 元件间距检查：只比较位置字典里相邻的 4 个元件（非空间最近邻），结论不可复现。
    - 去耦电容距离：把「除电阻/电感外的所有元件」当 IC（咪头、蜂鸣器、电池座），报出的「112 个去耦电容」其实是配对数。
    - 天线效应检查：`len(net.pins)<=1` 就累计报警；实测全库 10273 网络中 ≤1 引脚占 ~10%，
      个别设计（AirLink 535 网络里 214 个零引脚）是 pins 数据缺失导致的大面积误报。

11. **其余结构性判据问题**（详表见第 4 节，均为「与具体板子无关」的代码级 bug）
    - 光耦规则用两字母 `PS` 子串 → 全部 TPS 电源芯片被判光耦，且「输入限流」要求电阻位号前缀 == 光耦位号前缀（U vs R 恒 0），有光耦必报；
    - 悬空引脚规则完全不读 netlist，见 MCU 就报第一条；运放反馈规则的「同前缀」取的是运放自己位号的字母；
    - 板边间距规则用元件原点绝对坐标比 3mm，完全没用板框（DAPLINK 全板最小 3.373mm 却报 27 条）；
    - 测试点覆盖规则没有任何 TP/测试焊盘检测（解析器其实能读出 TP 位号）；
    - 电池分压规则的「电池供电系统」来自料号子串 `BAT54CT`；
    - 模数分离规则用两字母 `AD` 命中描述「PicoBlade」把 FPC 连接器当模拟器件；
    - 反接保护规则的 `protection_kw` 里没有 SS34 → 板上明明有肖特基也判「未检测到」；
    - 工程 BOM 的 pn/desc 全空时，所有关键词规则先天失明（ESP-HDMI-Bridge 的 ESD 阵列真实存在）。

### 建议的修复顺序（性价比排序）

1. 电源载流 `is_inner` 按层判定（1 行改动，影响 23/76 板、ERROR 级）
2. E24 查表 10× 比例 bug（1 行改动，占全库 779 条违规）
3. 器件分类改用「位号前缀 + 封装 + value」而非描述子串（影响 8 条规则）
4. 特征阻抗：差分用 `differential_impedance` + 差分目标，非高速网络不报
5. 提示类规则加 `kind: advise`，覆盖率口径只统计 detect 类

## 7. 对论文/汇报口径的建议

1. **不要把 61/71（有输出）写成准确率**；改为三个数并排：可判定 71/71、判定类精确率（本报告 13.9% 只是修之前的基线）、提示类条数单列。
2. 报「检出能力」时用**抽样精确率 + Wilson 区间**，并附样本量、判读口径与证据文件（可复现、可复核）。
3. 缺陷数（5769）目前不可用：先修第 6 节 1/2/4/5/9 五条（都是确定性判据错误），重跑覆盖率后再报数。
4. 阈值校准（0.5mm、3W、0.1mm、50mm…）应带**接口类型/层数**维度，而不是全库单一阈值。
